# شیفت‌یار ☕ — مدیریت شیفت و چک‌لیست کافه

یه PWA ساده (بدون نیاز به build و npm) برای:
- انتخاب شیفت هفتگی توسط ۴ باریستا (هرکس ۲ شیفت + ۱-۲ آف دلخواه)
- تکمیل و انتشار برنامه توسط مدیر
- سیستم جایگزینی شیفت (کسی نمی‌تونه بیاد → می‌ذاره روی تابلوی عمومی → هرکی خواست قبول می‌کنه)
- چک‌لیست مرحله‌به‌مرحله‌ی باز و بست کافه
- نوتیف داخل‌اپ + تلگرام (و آماده برای پیامک در آینده)

فرانت‌اند خالص HTML/CSS/JS ماژولار (بدون React/Vite) هست تا هر جایی — حتی یه هاست ساده استاتیک — قابل دیپلوی باشه. بک‌اند و دیتابیس روی **Supabase** (رایگان برای این حجم استفاده).

> 🔄 **قبلاً `schema.sql` رو اجرا کردی؟** فقط کافیه `supabase/updates_1.sql` رو هم تو SQL Editor اجرا کنی — رفع باگ تداخل شیفت/آف و موتور تولید خودکار برنامه رو اضافه می‌کنه، بدون اینکه چیزی که داری خراب بشه.

---

## ۱) ساخت پروژه‌ی Supabase

1. برو [supabase.com](https://supabase.com) → پروژه جدید بساز (منطقه‌ی نزدیک، مثلاً Frankfurt/Singapore).
2. از **SQL Editor**، کل فایل `supabase/schema.sql` رو کپی و Run کن.
   این کار جدول‌ها، RLS، دو تابع RPC (`accept_swap`, `toggle_checklist_item`)، ویو `team_directory` و یه چک‌لیست نمونه رو می‌سازه.
3. از **Project Settings → API**، مقدار `Project URL` و `anon public key` رو بردار.

## ۲) ساخت حساب برای ۴ باریستا + خودت (مدیر)

از **Authentication → Users → Add user** (یا از SQL) برای هرکدوم یه کاربر بساز:
- ایمیل داخلی مثل `sara@cafe.local` (نیازی به ایمیل واقعی نیست)
- رمز = همون رمزی که می‌خوای موقع ورود وارد کنه (می‌تونه PIN ۴ رقمی باشه)

بعد برای هرکدوم یه ردیف تو جدول `profiles` بساز (Table Editor یا SQL)، با همون `id` که Supabase بهش داد:

```sql
insert into profiles (id, name, role, color) values
  ('UUID-کاربر-۱', 'سارا', 'barista', '#C9A227'),
  ('UUID-کاربر-۲', 'امیر', 'barista', '#6B8F71'),
  ('UUID-کاربر-۳', 'نگار', 'barista', '#7C86C9'),
  ('UUID-کاربر-۴', 'رضا',  'barista', '#E3B341'),
  ('UUID-کاربر-مدیر', 'مدیر کافه', 'admin', '#B4432E');
```

نکته: چون RLS اجازه‌ی insert توسط خود کاربر رو هم می‌ده، هر باریستا با اولین لاگین می‌تونه پروفایل خودش رو هم بسازه — ولی ساده‌تره خودت از قبل بسازی‌شون.

## ۳) تنظیم فایل config

فایل `js/config.js` رو باز کن و این‌ها رو با مقادیر خودت جایگزین کن:

```js
export const SUPABASE_URL = "https://xxxx.supabase.co";
export const SUPABASE_ANON_KEY = "eyJhbGciOi...";
export const CAFE_NAME = "کافه‌ی شما";
```

## ۴) اجرای محلی (تست)

نیازی به build نیست، فقط یه سرور استاتیک ساده لازمه (چون ES Modules نیاز به http:// دارن، نه file://):

```bash
cd cafe-app
python3 -m http.server 8080
# یا: npx serve .
```

بعد `http://localhost:8080` رو باز کن.

## ۵) دیپلوی (تولید) — هاست لیارا (چون Netlify/Vercel فیلترن)

1. برو [liara.ir](https://liara.ir) و با شماره موبایل ایرانی ثبت‌نام کن.
2. از داشبورد، «برنامه‌های ابری» → «برنامه جدید» بزن.
3. پلتفرم رو **Static** انتخاب کن، یه اسم بذار (مثلاً `cafe-shift`)، و منطقه/بسته‌ی رایگان رو انتخاب کن.
4. پوشه‌ی `cafe-app` رو (بعد از اینکه `js/config.js` رو پر کردی) به‌صورت zip در بیار.
5. توی صفحه‌ی استقرار برنامه، فایل zip رو با drag & drop توی باکس آپلود بنداز و روی «استقرار» بزن.
6. بعد از چند لحظه، یه آدرس شبیه `https://cafe-shift.liara.run` بهت می‌ده — همینه که باید رو گوشی‌ها باز بشه.

⚠️ چون Service Worker فقط روی HTTPS کار می‌کنه، لیارا به‌صورت پیش‌فرض HTTPS می‌ده، پس مشکلی نیست.

اگه بعداً خواستی دامنه‌ی خودت (مثلاً `app.کافه‌شما.ir`) رو وصل کنی، از بخش «دامنه‌ها»ی همون برنامه توی لیارا انجامش بده.

## ۶) اتصال به تلگرام (نوتیف)

1. با [@BotFather](https://t.me/BotFather) یه بات بساز و توکنش رو بگیر.
2. Supabase CLI رو نصب کن و لاگین کن، بعد:
   ```bash
   supabase functions deploy notify-telegram --project-ref YOUR_PROJECT_REF
   supabase secrets set TELEGRAM_BOT_TOKEN=123456:ABC... --project-ref YOUR_PROJECT_REF
   ```
3. هر باریستا باید یه‌بار به بات پیام `/start` بده. بات باید `chat_id` رو برگردونه (ساده‌ترین راه: یه بات کوچیک با پکیج `python-telegram-bot` که فقط `update.effective_chat.id` رو echo کنه، یا از @userinfobot استفاده کن).
4. اون `chat_id` رو تو تب **مدیریت ← تنظیمات تیم** جلوی اسم هر باریستا وارد و ذخیره کن.
5. برای اینکه پیام‌ها خودکار ارسال بشن (بدون نیاز به کد اضافه تو فرانت‌اند)، تو Supabase Dashboard **دو تا** وبهوک بساز (**Database → Webhooks → Create a new hook**):
   - وبهوک اول — برای جایگزینی شیفت:
     - Table: `swap_requests`
     - Events: `Insert` و `Update`
     - Type: `Supabase Edge Function` → `notify-telegram`
   - وبهوک دوم — برای اطلاع‌رسانی برنامه‌ی هفته:
     - Table: `weeks`
     - Events: `Update`
     - Type: `Supabase Edge Function` → `notify-telegram`

از این به بعد، هم موقع باز/قبول‌شدن جایگزینی، هم موقع «تأیید و انتشار» برنامه‌ی هفته (که جدول کامل رو می‌فرسته)، پیام تلگرام خودکار می‌ره.

## ۷) پیامک (در آینده)

جدول `profiles` از الان یه ستون `phone` داره. وقتی خواستی، `notify-telegram` رو (یا یه فانکشن جدید `notify-sms`) با یه سرویس پیامکی ایرانی (مثل Kavenegar یا SMS.ir) وصل کن — همون الگوی وبهوک روی `swap_requests` عیناً کار می‌کنه، فقط تابع ارسال عوض می‌شه.

## نکات مهم درباره‌ی منطق برنامه

- **هفته** با یه ردیف در جدول `weeks` نمایش داده می‌شه که وضعیتش این مسیر رو طی می‌کنه:
  `bidding` (در حال رأی‌گیری) → `draft` (خودکار ساخته شده، منتظر تأیید مدیر) → `published` (نهایی و اطلاع‌رسانی‌شده) → `locked` (آرشیو).
- در حالت `bidding`، هر باریستا حداکثر ۲ شیفت و حداکثر ۲ آف انتخاب می‌کنه؛ این محدودیت و «همزمان شیفت+آف نشه» هر دو **سمت دیتابیس** هم چک می‌شن (نه فقط ظاهر برنامه)، پس حتی با باگ فرانت‌اند دیتا خراب نمی‌شه.
- مدیر از تب **مدیریت**، هر وقت خواست (یا بعد از مهلتی که خودش تنظیم کرده)، دکمه‌ی «بستن رأی‌گیری و تولید خودکار برنامه» رو می‌زنه. اینجا تابع دیتابیسی `generate_schedule` اجرا می‌شه که:
  1. اول انتخاب‌های خودِ باریستاها رو اعمال می‌کنه (اگه دو نفر یه اسلات رو خواستن، اولین ثبت‌شده می‌بره).
  2. به کسی که هیچ آفی انتخاب نکرده، خودش یه روز آف منصفانه می‌ده.
  3. بقیه‌ی اسلات‌های خالی رو با اولویت «کسی که تا الان کمترین شیفت رو داره» پر می‌کنه، و تا حد امکان از اینکه یه نفر شبِ یه روز و صبح فردا رو پشت‌سرهم کار کنه جلوگیری می‌کنه.
- نتیجه یه **پیش‌نویس (`draft`)** می‌شه که فقط مدیر می‌بینه — باریستاها هنوز چیزی نمی‌بینن. مدیر می‌تونه هر اسلات رو با کشوی کنارش دستی عوض کنه، یا «پاک کردن پیشنهادهای خودکار و تولید دوباره» بزنه (این کار فقط چیزهایی که خودِ سیستم پیشنهاد داده رو پاک می‌کنه، انتخاب‌های خودِ باریستاها و ویرایش‌های دستیِ مدیر دست‌نخورده می‌مونن).
- وقتی مدیر «تأیید و انتشار» رو بزنه، وضعیت `published` می‌شه، برنامه تو صفحه‌ی همه‌ی باریستاها ظاهر می‌شه، و (اگه تلگرام وصل باشه) جدول کامل هفته براشون تو تلگرام هم می‌ره.
- بعد از انتشار، هر باریستا از تب **برنامه** روی شیفت خودش دکمه‌ی «جایگزین» رو می‌زنه؛ شیفت با وضعیت باز روی تب **جایگزینی** برای همه دیده می‌شه؛ اولین نفری که «قبول می‌کنم» بزنه (از طریق تابع اتمیک `accept_swap` در دیتابیس) مالک شیفت می‌شه — رقابت هم‌زمان دو نفر با `for update` در دیتابیس هندل می‌شه.
- چک‌لیست‌ها به‌ترتیب باز می‌شن: نمی‌شه مرحله‌ی سوم رو قبل از تیک‌خوردن مرحله‌ی اول و دوم زد (تابع `toggle_checklist_item`).
- همه‌چیز Realtime هست: اگه یه نفر شیفتی رو جایگزین کنه، آیتمی رو تیک بزنه، یا مدیر برنامه رو منتشر کنه، بقیه‌ی گوشی‌ها بدون رفرش آپدیت می‌شن.
- **ادمین شیفت انتخاب نمی‌کنه** — تب «برنامه» فقط برای باریستاهاست؛ ادمین فقط تب «مدیریت» (+ جایگزینی/چک‌لیست) رو می‌بینه، و توی لیست «کی این شیفت رو بگیره» هم اصلاً به‌عنوان گزینه ظاهر نمی‌شه.

## خروجی متنی جدول برنامه

از تب **مدیریت**، وقتی هفته منتشر شده، دکمه‌ی «📋 خروجی متنی جدول» یه متن مثل این می‌سازه و کپی می‌کنه (برای گروه تلگرام، اینستاگرام استوری، هرجا):

```
📅 برنامه هفته ۱۴ الی ۲۰ شهریور

شنبه:
  صبح: سارا
  میدل: امیر
  شب: نگار
...
```

همین متن، دقیقاً به همین شکل (با HTML ساده برای بولد کردن)، خودکار موقع «تأیید و انتشار» به تک‌تک باریستاهایی که چت‌آیدی تلگرامشون ثبت شده فرستاده می‌شه — نیازی به کپی‌پیست دستی نیست، مگر بخوای جای دیگه‌ای هم بفرستیش.

## محدودیت‌های شناخته‌شده (برای توسعه‌ی بعدی)

- ویو `team_directory` ایمیل داخلی باریستاها رو قبل از لاگین قابل‌مشاهده می‌کنه (ریسک کمی داره چون ایمیل واقعی نیست، فقط شناسه‌ی داخلیه) — برای تیم بزرگ‌تر بهتره جایگزین با OTP پیامکی بشه.
- محدودیت «حداکثر ۲ شیفت / ۲ آف» فقط سمت کلاینت چک می‌شه؛ اگه بخوای ۱۰۰٪ سخت‌گیرانه باشه، باید Trigger دیتابیسی هم اضافه کنی.
- آیکون‌های PWA ساده و placeholder هستن — دلت خواست با لوگوی خودِ کافه عوضشون کن (`icons/icon.svg`).
